# 🛒 Grocery Store Management System — SQL

A MySQL database project that models a grocery-store operation and uses SQL queries to analyze customers, products, suppliers, orders, sales, and employee performance.

## 📌 Project Overview

The project follows a complete SQL workflow:

**Database creation → Schema design → CSV data import → Relational analysis → Business insights**

The database contains separate tables for suppliers, categories, employees, customers, products, orders, and order details.

## 🎯 Objectives

- Design a normalized relational database for a grocery store.
- Establish primary-key and foreign-key relationships.
- Import data while respecting referential integrity.
- Analyze customer purchasing behavior.
- Measure product and category performance.
- Study sales and order trends.
- Analyze supplier contribution.
- Evaluate employee order-handling performance.
- Perform deeper order-detail analysis.

## 🗄️ Database Schema

Database name:

```sql
grocery_store
```

### Tables

| Table | Purpose |
|---|---|
| `supplier` | Stores supplier information |
| `categories` | Stores product categories |
| `employees` | Stores store employees |
| `customers` | Stores customer information |
| `products` | Stores products, prices, suppliers, and categories |
| `orders` | Stores customer orders and responsible employees |
| `order_details` | Stores products, quantities, unit prices, and total prices |

### Relationships

```text
supplier ────────┐
                 ├── products ──── order_details ──── orders ──── customers
categories ──────┘                                      │
                                                        └── employees
```

The schema uses foreign keys with `ON UPDATE CASCADE` and `ON DELETE CASCADE` where defined in the SQL script.

## 📊 Analysis Areas

The SQL script contains **25 analysis questions** grouped into six areas.

### 1. Customer Insights

Queries answer questions such as:
- How many unique customers have placed orders?
- Which customers place the most orders?
- What is the total and average purchase value per customer?
- Who are the top 5 customers by total purchase amount?

### 2. Product Performance

Analysis includes:
- Product count by category
- Average product price by category
- Top products by quantity sold
- Revenue generated by product
- Product sales by category and supplier

### 3. Sales and Order Trends

The project calculates:
- Total number of orders
- Average order value
- Dates with the highest order volume
- Monthly order and revenue trends
- Weekday vs. weekend order patterns

The project uses `STR_TO_DATE()` and `DATE_FORMAT()` to analyze dates stored as `VARCHAR`.

### 4. Supplier Contribution

Analysis includes:
- Number of suppliers
- Supplier with the most products
- Average product price by supplier
- Supplier contribution to revenue and units sold

### 5. Employee Performance

Queries measure:
- Number of employees who processed orders
- Orders handled by each employee
- Total sales value processed by each employee
- Average order value handled per employee

### 6. Order Details Deep Dive

The project also examines:
- Quantity vs. total price
- Average quantity ordered per product
- Unit-price variation using minimum, maximum, average, and standard deviation

## 📥 Data Import

The SQL script expects CSV files to be imported in this order to satisfy foreign-key dependencies:

```text
1. Suppliers.csv
2. Categories.csv
3. Store_Employees.csv
4. Customers.csv
5. Products.csv
6. Orders.csv
7. OrderDetails.csv
```

The script also provides a `LOAD DATA INFILE` example and explains the corresponding CSV-to-table column mappings.

## ▶️ How to Run

### 1. Open MySQL Workbench

### 2. Run the database and table creation section

```sql
CREATE DATABASE IF NOT EXISTS grocery_store;
USE grocery_store;
```

### 3. Import the CSV files

Import parent tables before child tables.

### 4. Run the analysis queries

Execute the queries in the analysis section to reproduce the customer, product, sales, supplier, employee, and order-detail analysis.
